# Quant 观察池历史时机样本审计

## 背景

历史时机回看已能对单票和最多 3 只候选给出 Wilson 区间结论，但仓库下一步是用观察池更多已有标的检查各状态是否真的分开。紫金样本不足、特变区间重叠，不能据此改阈值。用户需要一次看到全池各状态的跨标的分布，而不是再手工点开详情。

## 目标

- 在 Overview 对观察池已有标的运行历史时机审计，复用现有日线 API 和 `buildTimingHistory`。
- 按状态统计有多少标的是样本不足、区间重叠、相对基准有稳定支持或相对基准偏弱。
- 加载中、来源失败、数据不足保持独立可见；不把不同股票的收益率合并成一个胜率或排名。
- 无论分布如何，都明确提示不调整状态阈值，不把审计结果写成买卖判断。

## 非目标

- 不新增 API、D1 字段、provider 或数据库迁移。
- 不修改 MA20/MA60/回撤阈值，不修改 Wilson 区间规则。
- 不把审计结果写入候选排序、价值质量、研究动作、AI 结果、决策就绪度或买卖建议。
- 不实现后台定时研究自动化。

## 影响与风险

- Quant 前端 Overview 增加显式“运行审计”动作；最多遍历观察池 50 只，日线请求复用 520 根上限和有限并发。
- 审计中途观察池变化时忽略过期请求。
- 现有比较抽屉、详情页历史回看和决策公式保持不变。
