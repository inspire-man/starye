## Context

候选快照已经以 JSON 保存于 `quant_scan_snapshot`，并保留最近 30 个有效快照。当前 `/api/quant/candidates` 只读取最新快照，Quant 前端已有候选表和右侧分析详情抽屉。实现需要保持同步写入和 D1 表结构稳定。

## Goals / Non-Goals

**Goals:**

- 在服务端集中读取和计算历史持续性，确保 API、表格和抽屉使用同一口径。
- 对历史不足、未出现在最新快照、分数变化和因子频次给出确定且可测试的结果。
- 限制证据明细数量，保持单次候选请求可控。

**Non-Goals:**

- 不新增数据库迁移、后台定时任务或新的数据 provider。
- 不把持续性状态解释为买入、卖出或收益预测。
- 不改动现有因子公式、快照保留策略或价值质量评分。

## Decisions

### 1. 复用快照表，不增加投影表

新增 repository 历史读取函数，按生成时间倒序取最多 30 条有效快照。候选 JSON 经过服务端的窄化解析后交给纯函数计算；这样保留现有权威数据链，也避免为派生统计引入迁移和一致性维护。

### 2. 相邻变化与首末变化同时返回

相邻分数变化用于判断“持续确认/信号减弱”，首末变化用于观察整个样本窗口的方向。股票在前一快照缺席时不跨越缺失快照寻找“前次分数”，避免把不连续样本说成连续确认。

### 3. 固定因子集合与有限证据

因子统计使用 `ma5`、`ma20`、`new_high_20`、`continuation`、`volume_ratio`、`relative_strength` 六个稳定键。API 为每只股票保留最近 5 条证据，完整样本数仍单独返回；前端展示因子计数和证据行，避免重复传输完整 30 次候选详情。

### 4. 兼容历史/异常 JSON

无法解析的候选项被视为缺席；缺失数值保持 `null`。客户端对没有持续性字段的旧响应使用“历史不足”默认值，确保开发环境中旧 fixture 仍能被解析。

## Risks / Trade-offs

- [历史快照间隔不固定] → 页面将其称为“最近 N 次快照”，不表述为连续交易日，并保留生成时间。
- [候选 JSON 体积随观察池增长] → 服务端只返回每只股票最近 5 条证据和聚合统计，不返回完整历史候选列表。
- [缺席可能来自数据不足] → 状态使用“不在最新快照”或“历史不足”，并在页面提示先更新数据，不自动推断负面信号。

## Migration Plan

无需迁移。先部署 API 和前端兼容字段，再通过现有日线同步生成新快照；回滚时移除新增读取和展示字段即可，历史表内容保持不变。
