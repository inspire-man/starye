## Why

现场复核显示 Quant 的日线同步、价值质量和股东回报数据都能独立返回，但这些状态分散在观察池、候选和股票详情页面。用户打开工作台时无法快速判断当前哪些研究数据完整、哪些只是部分可用，以及缺口来自读取中、上游状态还是实际字段不足。

## What Changes

- 新增前端纯函数，聚合同步状态、日线覆盖、价值质量和股东回报的当前数据健康状态。
- 在 Quant 总览增加数据健康区域，逐项显示完整、部分可用、待补、读取中或读取失败及其计数/来源时间。
- 复用现有已认证 API 返回，不新增请求、API route、D1 表、provider 或评分字段。
- 明确数据健康是可用性摘要，不改变信号分、价值质量分、研究优先级或交易判断。

## Non-Goals

- 不为外部 provider 增加 fallback、重试或新的数据源。
- 不把缺失字段、provider 配额或读取失败折算为零值。
- 不改变候选筛选、排序、同步写入、研究报告和持久化语义。

## Impact

- `apps/quant-app/src/lib/data-health.ts`：新增可测试的数据健康聚合模型。
- `apps/quant-app/src/lib/__test__/data-health.test.ts`：覆盖完整、部分、读取中、失败和空观察池状态。
- `apps/quant-app/src/App.vue`：在总览接入聚合状态和可访问展示。
- `apps/quant-app/src/style.css`：增加数据健康区域的密集、响应式和状态样式。

## Risks

- 多个 API 模块独立加载，摘要必须区分未加载、失败和无数据，避免误报为完整或无记录。
- 各计数来自不同数据边界，展示必须保留来源语义，不把价值质量结果解释为证据覆盖或买卖信号。

## Verification

- Quant 总览 MUST 使用当前已加载数据展示各数据域的真实状态；数据健康摘要 MUST 不触发额外网络请求或状态写入。
- 页面 MUST 在 390px 视口保持无横向溢出，并在控制台无 error/warn。
