# 背景

Quant 详情已经可以按需生成单股 AI 证据解读，也可以在候选对比中生成多股 AI 对比，但用户遇到具体疑问时仍需要自己阅读整份报告。现有 AI 结果没有提供围绕当前报告继续追问的入口，接入 AI 的感知仍然偏弱。

# 目标

- 在当前股票已有研究报告时提供主动提问入口。
- 服务端只基于当前登录用户拥有的研究运行重新读取报告，回答用户问题并返回可核对的 evidence key 引用。
- 对 AI 配置缺失、报告不存在、问题无效、上游失败和非法引用显示诚实状态。
- 提问结果只存在于当前页面，不写入研究历史或 D1。

# 非目标

- 不新增会话、聊天历史、D1 表、服务端分享链接或持久化问答记录。
- 不把前端提交的报告正文或 API key 转发给模型。
- 不修改确定性评分、研究动作、候选排序、研究标记或既有 AI 摘要/对比结果。
- 不允许回答生成买入、卖出、目标价、止损价或收益预测。

# 影响

- API：新增研究报告提问 domain、请求/响应 schema、认证路由和集成测试。
- Quant：新增提问类型与 client 方法，在详情抽屉增加问题输入、加载/失败/成功状态和 evidence 跳转。
- 数据库：不新增 schema 或迁移；提问结果不持久化。
- OpenSpec：记录接口边界、AI 输出校验和页面验收条件。

# 风险

- 模型可能回答报告之外的内容或混淆 evidence key，需要服务端限定 prompt、响应字段和引用白名单。
- 用户连续切换股票或重复提交问题可能造成过期响应覆盖当前页面，需要 request id 和提交锁。
- 问题与回答可能很长，需要限制输入、prompt、响应和移动端布局，避免页面溢出。

# 可验证需求

- Quant MUST 在当前用户有已加载研究报告时允许主动提交一个问题，并返回只基于该报告事实的结构化回答与 evidence 引用。
- AI 提问失败或引用非法时 MUST 显示失败状态，且不得修改或持久化研究报告及确定性数据。
