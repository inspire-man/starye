## 设计

### 数据流

`openComparisonDrawer` 在现有估值和财务读取之外，为每个选中候选调用 `quantApi.getDailyBars(tsCode, { limit: 520 })`。结果按 `tsCode` 存入比较局部状态，调用现有 `buildTimingHistory` 派生摘要。API 与 D1 合同不变。

### 展示

比较表增加“历史时机回看”分组，每个候选列展示：

- 有效日线 / 非重叠截点；
- 当前状态；
- 全体上涨比例；
- 当前状态样本与样本等级；
- 当前状态上涨比例与相对全体 lift。

没有日线时显示读取中或来源不可用；日线少于 80 根时显示数据不足；状态样本少于 6 个时继续显示统计值但标记样本不足。

### 请求生命周期

每次打开比较抽屉递增一个 generation。日线请求完成后只有 generation 仍然匹配时才写入状态；关闭抽屉时递增 generation 并清空比较日线状态。估值、财务和研究历史请求继续使用各自的现有生命周期。

### 验证

- 组件测试覆盖摘要列、空数据、样本不足和旧请求结果被忽略。
- Quant 全量测试、type-check、build、OpenSpec strict、root lint 通过。
- Gateway 认证态用 `600089.SH` 与 `601899.SH` 选中两项，确认比较抽屉同时显示两只标的历史摘要；窄屏检查不出现页面级横向溢出。
