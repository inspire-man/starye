## 设计

### 批量边界

`runResearchAiSummaryBatch` 接收已成功研究运行的 `{ tsCode, runId }` 列表，按输入顺序去重并限制最多 3 项。默认并发为 2，超出范围的调用参数仍由编排器限制。每项先发出 `pending`，获得执行位后发出 `running`，最后发出 `success` 或 `error`；单项异常只写入该项结果。

### 状态与代次

Vue 页面维护 `tsCode -> { status, summary, error }` 的状态表。批量重新生成时重建整张表，失败项重试时只重置对应项，其他成功摘要保持不动。每次新批量操作或研究报告变化都递增请求代次；进度回调和 finally 只接受当前代次，避免旧请求回写新报告状态。

### API 与数据边界

每个 runner 只调用现有 `quantApi.generateResearchSummary(runId)`。摘要仍由服务端使用用户已保存的配置生成，浏览器不接触 API key。批量摘要状态不写入研究报告导出 formatter，因此现有下载和复制仍只反映确定性报告及其既有 AI 摘要。

### 交互与布局

对比抽屉在研究全部结束且至少有一项成功时显示“批量生成 AI 摘要”。按钮只在用户点击后发起请求，生成中禁用以防重复。每行在研究状态旁显示摘要状态；失败项显示“重试摘要”，成功项显示模型信息。操作区允许换行，状态文案可断行，保留 `aria-label`、`title`、`role="status"` 和可见焦点。

### 回滚

回滚时移除批量摘要编排器、对比抽屉入口和状态样式；现有单项摘要 API、研究报告、导出和复制能力不受影响。
