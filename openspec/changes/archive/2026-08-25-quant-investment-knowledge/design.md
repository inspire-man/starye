## Context

当前 Quant 已有 `value-quality-v1`，它通过估值、盈利质量、增长稳定性和趋势风险生成分数；文章提出的订单、资本开支、股息、行业和商品变量尚未接入 provider。文章中存在“变变”“海狗”“赵姨”等昵称，且若干公司属于港股或未上市主体。详细行为契约见 `specs/quant-investment-knowledge/spec.md`。

## Goals / Non-Goals

**Goals:**

- 用可追溯的来源和因子卡片解释当前评分体系。
- 把下一轮数据建设变成明确的字段清单，而不是直接增加猜测指标。
- 扩展一组明确的 A 股研究样本，覆盖金融、能源、周期、电力、设备、资源和半导体。

**Non-Goals:**

- 本轮不新增财务、股息、订单或商品 provider。
- 本轮不做文章全文存储、语义搜索或自动从文章抽取股票。
- 本轮不改变 `value-quality-v1` 的权重和评分结果。

## Decisions

### 1. 知识目录使用代码版本化定义

知识条目数量小、内容需要人工审阅，采用 Quant domain 内的只读定义模块。API 返回统一 JSON，前端只负责展示；后续数据接入完成后只更新因子的 `status` 和字段映射，保留相同的 source id 与 factor id。

### 2. 因子分为 active、partial、planned、context

- `active`：现有标准化估值、财务和日线字段足够计算，已由 `value-quality-v1` 覆盖。
- `partial`：已有部分证据，但缺少关键字段，页面展示方向和缺口，不进入总分。
- `planned`：文章观点明确且值得量化，但当前没有可靠数据契约。
- `context`：帮助理解公司或行业的定性知识，暂不量化。

### 3. 别名映射与观察池分离

别名目录保留所有文章实体，但只有 A 股代码、市场映射和 provider 支持范围均明确的记录进入 seed。港股代码记录为 context-only，避免把跨市场价格和报告期混入当前池内百分位。

### 4. Migration 只做 INSERT OR IGNORE

新增 migration 使用稳定 id 和唯一 `ts_code`，只在缺少目标行时插入名称。这样迁移执行过程中的重复 apply 不会复制记录，也不会覆盖用户后续名称编辑；迁移完成后运行时只读取观察池，不执行 seed，因此用户删除后不会在每次读取时自动回填。

### 5. 前端使用独立知识区域

工作台新增一个紧凑的“投资因子框架”区域，先显示状态统计，再显示 active/partial/planned 因子卡和“下一步数据”列表，来源与别名作为折叠式密集列表。知识区请求独立于价值评分，局部失败不影响择股数据面。

## Risks / Trade-offs

- [昵称误映射] 文章昵称可能指代其他标的 → 显示中等置信度、映射理由和 context-only 状态，不以隐称作为自动操作依据。
- [样本扩展造成同步耗时] 观察池从 4 只扩大到约 14 只 → 复用现有并发和总截止时间，先展示数据覆盖状态。
- [观点被误读为公式] 文章判断包含作者主观预期 → 每张因子卡显示“研究假设”，只有 active 因子进入现有评分。
- [来源可访问性变化] 微信页面或付费内容状态可能改变 → 只保存稳定 URL、标题和访问状态，不把一次读取结果当作持续事实。

## Migration Plan

1. 发布知识 API、前端知识区和幂等观察池 seed。
2. 通过本地 migration、D1 readback 和 Gateway 验证新增股票与知识接口。
3. 后续接入订单、资本开支、股息、行业和商品数据时，单独建立 provider/spec change，再把对应因子从 planned/partial 提升为 active。

## Open Questions

无。港股支持、行业分类和商品数据后续分别进入独立 change，避免扩大当前 A 股观察池的口径。
