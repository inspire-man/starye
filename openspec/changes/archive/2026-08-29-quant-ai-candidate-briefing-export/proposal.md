## 背景

候选 AI 简报已经可以按需生成，并展示整体概览、重点候选、下一步核对项和引用代码，但结果只存在于当前页面状态中。用户完成一次候选研究后缺少本地留存、复制或交给后续人工复核的轻量出口。

## 目标

- 在简报成功态提供 Markdown 复制和本地文件导出。
- 导出内容保留简报版本、生成时间、候选范围、重点候选的确定性研究字段、核对项和引用代码。
- 复制与导出只读取当前页面已解析的简报，不触发网络请求，也不改变候选数据。

## 非目标

- 不新增 API、D1 表、provider、后台任务或简报持久化记录。
- 不自动触发 AI 请求，不改变候选筛选、排序、评分、研究动作或研究标记。
- 不把 API key、token、cookie、provider 配置或未列入白名单的对象字段写入剪贴板或文件。

## 影响

- `apps/quant-app/src/lib/candidate-briefing-export.ts`：新增纯 Markdown formatter 和稳定文件名。
- `apps/quant-app/src/components/QuantAiCandidateBriefing.vue`：增加复制/导出操作和复制状态。
- `apps/quant-app/src/App.vue`：复用现有剪贴板工具接入本地复制与下载动作。
- `apps/quant-app/src/lib/__test__/` 与组件测试：覆盖字段白名单、缺失值、复制状态和下载事件。

## 风险

- AI 文本可能含换行或 Markdown 特殊字符；formatter 将单行元数据和列表项压平，并只输出明确允许的字段。
- 浏览器剪贴板可能不可用或拒绝写入；页面必须显示可重试的错误状态，不把复制成功当作已发生。
- 当前简报被刷新后旧复制结果可能仍显示；父页面在候选数据变化时重置复制状态，并用请求序号隔离异步结果。
