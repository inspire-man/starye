## Context

See `proposal.md` for the motivation. Quant 详情抽屉已经接入 `DailyBar`、`buildTrendStructure` 和 `buildTimingWindow`；当前选中股票通常有最近 120 根日线，足以构造一组有限的历史截点，但不适合声称具有统计预测能力。

## Goals / Non-Goals

**Goals:**

- 复用现有时机状态阈值，在每个历史截点只读取截点之前的数据。
- 统计未来 20 个有效交易日的方向比例、平均/中位数收益和极值，并明确样本数量。
- 让初学者能从当前状态跳转到同状态历史证据，不需要手工拼接表格。

**Non-Goals:**

- 不生成目标价、止盈止损、买入卖出指令或收益承诺。
- 不把历史回看结果加入候选排序、信号分或 API 响应。
- 不处理行业、估值或基本面历史回测，也不引入新的数据源。

## Decisions

### 1. 使用有效日线重放

先按交易日排序并保留正数有效收盘价。对每个截点 `t`，要求至少有 60 根历史有效收盘价和 20 根未来有效收盘价；状态只由 `bars[0..t]` 计算，未来收益使用 `close[t+20] / close[t] - 1`。这样可直接检查前视偏差，也不依赖自然日连续性。

### 2. 复用时机窗口分类

历史重放调用现有 `buildTrendStructure` 和 `buildTimingWindow`，不复制 MA、回撤和状态优先级阈值。若后续调整时机规则，历史证据会和当前状态同步变化。

### 3. 展示聚合证据而非排名

每个状态桶返回样本数、上涨样本比例、平均收益、中位数收益、最好和最差收益；空桶字段保持 `null`。面板优先展示当前状态桶，并保留四种可比较状态的紧凑行，避免把样本数量少的结果包装成排名。

### 4. 明确样本边界

面板展示“最近 N 根有效日线”和可回看的截点数量，说明窗口存在重叠、样本量有限且只描述历史。信息图标 tooltip 说明它不是预测或交易指令。

## Risks / Trade-offs

- [样本量少或窗口重叠] → 展示样本数和数据范围；少于一个可回看窗口时显示数据不足。
- [历史状态受当前规则版本影响] → 复用 `buildTimingWindow`，并显示当前因子版本/本地日线口径。
- [有效日线不等于连续自然日] → 所有文案使用“有效交易日”，不使用日历天数推断。

## Migration Plan

无需迁移。前端在已有日线加载后即时计算；回滚只移除纯函数、测试和抽屉面板，不影响 API、数据库和已保存数据。
