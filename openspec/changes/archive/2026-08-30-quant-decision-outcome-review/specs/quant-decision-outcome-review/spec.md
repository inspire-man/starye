# Quant 决策结果回看

## ADDED Requirements

### Requirement: 计算可复核的后续价格观察

系统 MUST 对历史决策记录按快照价格日期排序，只把 `plan-buy` 和 `holding` 作为价格观察起点；起点价格和后续观察价格都必须是大于 0 的有限数值，观察日期必须严格晚于起点日期。

#### Scenario: 与下一次决策记录比较

- **WHEN** 起点记录存在有效价格，之后存在一条有效价格的决策记录
- **THEN** 系统使用之后第一条有效价格记录计算百分比变化，并保留观察记录的 action 和时间

#### Scenario: 与最新日线比较

- **WHEN** 起点记录之后没有有效的后续决策记录，但页面提供了更晚的有效最新日线
- **THEN** 系统使用最新日线生成一条“当前观察”结果

#### Scenario: 数据不足

- **WHEN** 起点价格、后续价格或严格递增日期缺失
- **THEN** 系统显示待观察状态，不计算价差，不填充默认价格

### Requirement: 结果语义必须与实际收益分离

结果回看 MUST 将记录价差、已卖出配对和当前观察分别标记；页面 MUST 明确说明它不包含实际成交价、数量、费用、税费或分红。

#### Scenario: 已卖出配对

- **WHEN** 有效的计划买入或已持有起点之后第一条有效后续记录的 action 是 `sold`
- **THEN** 结果标记为已卖出配对，并显示起点价格、卖出记录价格和价格变化

#### Scenario: 普通后续记录

- **WHEN** 后续有效记录的 action 不是 `sold`
- **THEN** 结果标记为后续观察，不使用“盈利”“亏损”或“收益率”措辞

### Requirement: Quant 页面支持响应式回看

Quant 决策记录区域 MUST 展示结果回看摘要、有限数量的观察条目、空状态和数据不足说明；在 390px 宽度下不得产生横向溢出，且结果区域不得触发新的 API 或 AI 请求。

#### Scenario: 没有足够历史

- **WHEN** 用户只有继续观察记录，或只有一个无后续价格的计划买入/持有记录
- **THEN** 页面显示待观察提示和边界说明，不显示伪造的百分比

#### Scenario: 移动端查看

- **WHEN** 用户在 390px 宽度打开决策记录
- **THEN** 摘要、价差条目和说明文本都在容器内换行，交互区域保持键盘可达
