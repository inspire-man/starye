# Quant 证据链与时机研究

## ADDED Requirements

### Requirement: 观察池新增必须尽力补齐名称

Quant watchlist create API MUST 在用户未提供名称时使用已配置的公开行情资料解析证券简称；用户提供的非空名称 MUST 优先于解析结果。解析失败 MUST 保留代码写入结果，并返回可识别的名称缺口，不得把失败伪装成有效名称。

#### Scenario: 仅输入代码

- **WHEN** 已认证用户提交合法的 `ts_code` 且 `name` 为空
- **THEN** API 尝试解析证券简称并返回持久化后的 `tsCode` 和 `name`
- **AND** 后续观察池列表与候选研究使用同一个名称

#### Scenario: 名称解析失败

- **WHEN** 公开行情资料超时、返回空数据或代码不匹配
- **THEN** 代码仍按现有 CRUD 规则写入
- **AND** `name` 保持 `null`，前端显示“名称待补齐”并保留手工补录路径

### Requirement: 候选研究必须反映当前观察池

`GET /api/quant/candidates` MUST 返回当前观察池与最近有效扫描快照的并集。当前观察池中没有快照记录的代码 MUST 以 `insufficient_data`、空指标和明确的待更新原因返回；已从观察池删除的代码 MUST NOT 继续显示为当前候选。

#### Scenario: 新增后尚未更新

- **WHEN** 用户新增观察股但尚未完成日线同步
- **THEN** 候选研究表显示该股票、名称、待更新状态和缺失字段
- **AND** 页面提供进入观察池新增和更新观察池的入口

#### Scenario: 完成更新

- **WHEN** 观察池日线同步成功或部分成功
- **THEN** 候选快照按当前观察池重算
- **AND** 每只股票保留数据窗口、因子版本、命中规则和缺口状态

### Requirement: 删除确认必须可预测定位

共享 `ConfirmDialog` MUST 支持可选的窄视口定位模式，并保持现有默认模式兼容其他应用。Quant 删除观察股 MUST 使用居中确认模式，遮罩覆盖当前视口，确认面板不得贴在页面内容左下角或受父级布局影响。

#### Scenario: Quant 窄视口删除

- **WHEN** 用户在 Quant 观察池点击删除
- **THEN** 确认面板位于当前视口中部，取消和确认按钮可见且可聚焦
- **AND** 关闭或取消后焦点回到原删除按钮

### Requirement: 研究结果必须提供硬证据链

分析抽屉 MUST 展示版本化的 `decision-evidence-v1` 证据链。每条证据 MUST 包含维度、原始指标、数据来源、观察时间或报告期、门槛、通过状态和缺失原因；缺失字段 MUST 保持缺失状态，不得推导为零或正向结论。

#### Scenario: 数据完整

- **WHEN** 股票具有足够日线、估值、财务报告和股东回报数据
- **THEN** 抽屉展示趋势、估值、经营质量、现金回报和风险门槛的逐项证据
- **AND** 展示最终研究动作及其由哪些证据通过/未通过推导而来

#### Scenario: 数据不完整

- **WHEN** 任一关键维度缺少数据或数据源失败
- **THEN** 该维度显示“数据不足”和具体缺口
- **AND** 时机结论降级为等待补齐/等待复核，不输出确定性买入或卖出判断

### Requirement: 中长线时机框架必须可复核

时机框架 MUST 面向中长线价值研究，至少覆盖趋势确认、估值安全边际、盈利/现金流质量、股东回报和风险复核五类门槛。框架 MUST 输出研究动作、等待条件、重新评估条件和公式版本，不得声称预测未来收益。

#### Scenario: 进入研究窗口

- **WHEN** 数据完整、估值未处于观察池高位、经营质量和趋势至少达到对应门槛且没有高风险扣分
- **THEN** 输出“进入研究窗口/分批观察”类动作，并列出通过门槛的原始数值

#### Scenario: 等待或重新评估

- **WHEN** 趋势过热、估值处于池内高位、现金流与利润背离、数据过期或关键门槛失败
- **THEN** 输出“等待确认/重新评估”类动作
- **AND** 明确触发条件，例如回到均线、估值回到样本中位区间、补齐报告或核对风险
