## Purpose

保证生产定时爬虫在大章节页面集和短暂控制面故障下仍能完成可读的持久化与生命周期回报，并保留已有事件绑定、幂等和权威读回边界。

## ADDED Requirements

### Requirement: 章节页面批量写入遵守 D1 变量边界

章节同步 MUST 将页面插入拆分为平台变量限制以内的批次；完整页面集替换 MUST 保留删除、插入和章节元数据更新的原子执行语义，并返回成功结果。

#### Scenario: 大章节页面集成功同步

- **WHEN** native D1 路径收到超过单条 SQL 安全页面数量的完整页面集
- **THEN** 每个插入语句的绑定变量数量处于配置的安全上限内，所有页面和 `source_page_count` 均可读回，章节同步返回成功

#### Scenario: 批处理失败保留既有页面

- **WHEN** 页面替换的任一批次在 native D1 或兼容数据库路径失败
- **THEN** 现有页面状态保持可读，调用方收到失败结果，并且后续批次不会继续扩大部分写入

### Requirement: Runner 控制面 5xx 使用同一事件身份重试

runner 控制请求收到 5xx 时 MUST 在有界次数内重试；重试 MUST 复用同一序号、event ID、nonce、请求体和签名。4xx 响应 MUST 继续按现有状态语义返回或抛出，超过重试上限后 MUST 暴露原始失败状态。

#### Scenario: 临时 5xx 后事件成功

- **WHEN** heartbeat、progress、log 或终态事件第一次收到 5xx，后续同一请求在重试窗口内成功
- **THEN** 服务端只处理一个事件身份，事件序列连续，runner 调用返回服务端成功结果

#### Scenario: 持续 5xx 达到上限

- **WHEN** 同一 runner 控制请求连续收到 5xx 直至达到重试上限
- **THEN** 客户端停止重试并报告最后的控制请求失败，后续事件序号由上层生命周期处理显式收口

#### Scenario: 客户端错误不触发重试

- **WHEN** runner 控制请求收到 4xx
- **THEN** 客户端立即保留现有错误处理语义，不发送额外同身份请求
