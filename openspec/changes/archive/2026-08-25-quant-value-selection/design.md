## Context

现有 `momentum-v1` 只依赖日线，并由同步流程持久化候选快照；估值和财务质量来自按股票即时读取的 Eastmoney provider。价值评分需要同时访问三类事实，又不能把临时外部数据写入 `quant_daily_bar`，因此本变更采用独立领域模块和批量读取接口。详细行为约束见 `specs/quant-value-selection/spec.md`，既有工作台边界见 `openspec/specs/quant-selection-workbench/spec.md`。

## Goals / Non-Goals

**Goals:**

- 形成中长线、偏价值风格且能向用户解释的 100 分制研究分数。
- 允许观察池扩展到现有 50 条上限，并使用池内有效样本进行相对位置计算。
- 对空值、负 PE、部分失败、报告期和观察日期采取 fail-closed 处理。
- 让前端先展示结论摘要，再能从抽屉回到分项事实。

**Non-Goals:**

- 不改变日线同步、`momentum-v1` 排序或现有估值/财务 provider 的字段含义。
- 不做行业排名：当前 `stock_basic.industry` 尚未接通，界面明确标注为“当前观察池”。
- 不新增评分快照表；外部估值和财务数据时效性不足以作为长期持久化事实。

## Decisions

### 1. 独立公式模块

新增纯函数 `value-quality.ts`，输入标准化估值、财务历史、最新候选和日线结构，输出维度分数、缺失字段、风险项与样本计数。`momentum-v1` 继续由原模块负责，避免一个版本同时代表短线动量和价值风格。

公式约定：

```text
总分 = 估值 35 + 盈利质量 30 + 增长稳定性 20 + 趋势风险 15 - 风险扣分
```

- 估值：正 PE(TTM)、PB、PS、PEG 使用池内百分位；低值优先，最多按有效字段归一化后计入 35 分。
- 盈利质量：ROE、ROIC、毛利率、净利率、经营现金流/营收为高值优先，资产负债率为低值优先；至少三个有效字段才可给完整维度分。
- 增长稳定性：营收同比、净利润同比、扣非净利润同比和最近报告序列的方向/波动；至少两期报告用于稳定性判断，增长与现金流背离进入风险项。
- 趋势风险：60/120 日价格结构、距长期均线和回撤作为辅助分；短期连续上涨、异常放量或较大回撤消耗风险分，不能压过经营维度。

### 2. 批量读取而非同步内嵌

新增受认证保护的批量 endpoint，在请求内读取当前观察池、最新候选和日线，再以最多 4 个并发任务分别请求估值与财务历史。目标是让“更新日线”保持快速、可重试；价值评分失败不会阻塞日线同步，也不会生成一份看似持久但时点混杂的数据库快照。

### 3. 部分失败契约

每只股票独立封装 `valuationStatus`、`financialStatus` 和 `status`。上游失败只影响该股票对应维度；全局响应仍返回 items 与 `failedCount`。错误只返回稳定的 Quant provider 错误类别，不把外部响应正文带到 UI。

### 4. 前端渐进展示

工作台加载候选后单独请求价值评分。表格显示“价值质量”状态/分数，详情抽屉显示四维分解与证据日期。加载失败时只显示该区块的重试状态，保留已有技术、估值和财务内容。移动端使用堆叠布局，不增加固定宽度表格。

## Risks / Trade-offs

- [上游限流] 观察池扩大后请求量线性增加 → 固定并发、批量接口逐只隔离失败，前端显示样本覆盖率。
- [报告期不同] 不同股票最新报告可能不是同一季度 → 返回每只报告期，比较文案限定为当前观察池的可用样本，不伪造同期一致性。
- [样本过少] 三只股票不足以形成稳定百分位 → 保留分项样本数，在 UI 标出“样本有限”，建议扩展观察池后再使用排序。
- [公式误读] 分数容易被误解为收益预测 → 使用“研究排序/观察”措辞，明确不代表未来收益，并允许查看原始指标。

## Migration Plan

1. 先发布纯函数、API 契约和前端兼容解析；旧 `momentum-v1` 响应无需迁移。
2. 部署后通过 Gateway 验证批量接口、部分失败和扩展观察池，再做桌面/移动端验收。
3. 回滚时移除前端价值区块和 API 路由即可，不涉及 D1 schema 或数据回填。

## Open Questions

无。行业字段接通后可另建 change，将“观察池百分位”扩展为行业内百分位，不改变本次接口的缺失和失败契约。
