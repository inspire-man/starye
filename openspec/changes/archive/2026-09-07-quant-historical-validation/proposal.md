# Quant 历史结论验证与时机算法校准

## 背景

当前时机历史回看只读取最近 120 根日线，并按每天滚动一个截点。连续截点共享大部分历史窗口和未来 20 日结果，容易把同一段行情重复计数；页面只展示状态上涨比例，没有全体样本基准，也没有样本可靠性提示。紫金矿业和特变电工的现有结果因此只能说明局部历史，不足以检验状态结论是否具有相对解释力。

## 目标

- 让日线同步和详情读取覆盖约两年的有效交易日，保留足够的旧数据用于两只标的的历史验证。
- 使用彼此不重叠的未来 20 个有效交易日作为回看样本，保留现有状态分类阈值，避免因统计口径变化误改当前信号。
- 为每个状态增加全体样本基准、相对基准差值、方向比例区间和样本等级。
- 在 Quant 详情页明确显示样本口径、样本等级和“相对全体”的结果；样本不足时显示不可验证，而不是显示伪准确率。
- 用 `600089.SH` 和 `601899.SH` 的真实历史日线完成 Gateway 证据验证。

## 非目标

- 不把历史回看接入候选排序、价值质量分、研究动作、决策就绪度或买卖判断。
- 不把上涨比例命名为预测准确率，不进行参数针对个股的拟合，不新增交易策略。
- 不新增数据库表或改变既有日线事实字段；旧数据通过已有同步链路重新获取。

## 影响

- API Quant 同步默认历史范围、每只股票保留条数、日线读取上限和 Eastmoney K 线请求上限。
- Quant 前端 `timing-history` 纯函数、详情面板、加载日线数量和相关测试。
- 不涉及 D1 schema、认证、AI、价值质量和决策接口。

## 风险

- 更长历史会增加 provider 响应体和同步耗时；保留现有并发、单请求超时和总超时边界。
- 某些标的历史不足或来源不可用时，页面必须保留明确缺口，不以零值补齐。
- 两只股票仍是小样本验证，结果只能作为研究证据，不能外推为普遍规律。
