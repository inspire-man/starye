## Context

Quant API 已按 `generatedAt` 倒序返回当前股票最近研究运行，前端 `researchRuns` 已加载最多 5 条，并使用第一条作为当前报告。本 change 仅消费这些现有数据，在 Quant app 中增加历史比较模块；不改变服务端 contract 或持久化模型。

## Goals / Non-Goals

**Goals:**

- 以 evidence key 为主键比较相邻报告。
- 先比较 status，再在两侧都有有限数值时计算 delta。
- 在详情抽屉中提供紧凑摘要，不替代完整的最新报告证据链。

**Non-Goals:**

- 不跨股票比较，不跨不同 evidence key 推断因果。
- 不把历史上涨比例或变化标签接入评分、动作或 AI 生成输入。

## Decisions

### 1. 前端纯函数比较

比较逻辑放入独立 TypeScript 模块，输入两个 `QuantResearchReport`，输出稳定排序的变化项和摘要计数。这样边界测试不依赖 Vue 或网络，页面只负责展示。

### 2. 状态优先、数值其次

状态从 `missing/fail/caution/pass` 的顺序判断改善或转弱；状态相同且两侧均有数值时再计算 delta。无法比较的项仍显示前后状态与 `--`，不把缺失当作零。

### 3. 限制展示规模

默认只展示有变化或缺失持续项的前 8 条，按风险优先、状态变化、数值变化排序；完整证据仍保留在最新报告区，避免抽屉过长。

### 4. 与当前报告分层

历史区放在最新报告和 AI 摘要之后，顶部显示“当前报告不受历史标签改变”的上下文。没有历史时显示空状态，不隐藏当前报告。

## Risks / Trade-offs

- [报告口径变化] -> 输出两次报告日期，且只按 stable key 对齐，不比较不同 key。
- [数据源日期不同] -> 变化项展示前后日期；数值不可比时保留状态变化，不强行计算 delta。
- [历史证据过多] -> 只展示变化和持续缺口的有限列表，完整数据留在报告中。

## Migration Plan

1. 仅部署 Quant Pages 静态资源，无 API/D1 migration。
2. 旧报告直接参与比较；缺失字段进入诚实的不可比较状态。
3. 通过 Gateway 验证有两次运行、单次运行和无历史三种页面状态。
