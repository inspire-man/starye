## ADDED Requirements

### Requirement: AI 摘要生成必须持久化终态运行审计

系统 MUST 为每次研究摘要生成尝试保存一条当前用户可回看的终态审计。审计 MUST 包含研究运行、provider、model、响应模式、有效生成预算、开始/完成时间、耗时、接收字符数和 `completed`、`failed` 或 `cancelled` 状态。成功审计 MUST 关联已持久化摘要；失败审计 MUST 区分错误码和可读原因。审计 MUST 不保存 prompt、密钥或完整 AI 输出。

#### Scenario: 完整摘要生成成功

- **WHEN** AI 返回完整内容且摘要结构校验、因子影响计算和 D1 摘要写入均成功
- **THEN** 系统保存 `completed` 审计并关联摘要 ID
- **AND** 审计中的接收字符数、耗时、响应模式和预算与本次运行一致

#### Scenario: AI 生成失败

- **WHEN** AI 超时、上游失败、内容不完整或结构化校验失败
- **THEN** 系统保存 `failed` 或 `cancelled` 审计以及受限错误码
- **AND** 本次失败不会创建新的研究摘要，既有摘要和确定性报告保持可读

### Requirement: 审计读取必须遵循用户和研究运行边界

系统 MUST 提供 `GET /api/quant/research/runs/:runId/ai-audits?limit=`，仅返回当前用户且属于该研究运行的审计。接口 MUST 限制返回数量并按完成时间倒序；跨用户或不存在的研究运行 MUST 返回 404。审计写入失败不得泄漏 prompt、密钥或完整响应。

#### Scenario: 用户读取自己的运行历史

- **WHEN** 已登录用户读取自己的研究运行审计
- **THEN** API 返回最近的终态运行列表和统一字段
- **AND** 列表可区分成功、失败、取消及对应耗时/错误原因

#### Scenario: 用户读取其他用户的运行

- **WHEN** 用户使用其他用户的研究运行 ID 请求审计
- **THEN** API 返回 404
- **AND** 不返回审计存在性或其他用户运行信息

### Requirement: 研究详情必须把运行可靠性与研究结论分开显示

Quant 页面 MUST 显示最近 AI 运行的状态、响应模式、预算、耗时、接收字数和摘要持久化状态。运行失败或信息缺失时，页面 MUST 保留确定性报告、因子覆盖和历史摘要，并允许沿用现有生成/重试入口。运行审计不得被展示为买入、卖出或收益预测。

#### Scenario: 用户检查一次 AI 结果是否完整

- **WHEN** 研究详情存在 completed 审计
- **THEN** 页面显示已完成、接收字数、耗时、预算和已保存摘要
- **AND** 用户可以将这些运行事实与确定性研究结论分开判断

#### Scenario: 用户查看失败后重试

- **WHEN** 最近一次 AI 尝试失败但存在确定性报告或旧摘要
- **THEN** 页面显示错误码/原因和失败运行历史
- **AND** 旧摘要与确定性报告继续显示，生成按钮保持可用
