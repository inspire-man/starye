# Quant 结构化研究运行

## 背景

当前 Quant 工作台已经分别提供日线候选、估值、财务质量、股东回报和决策证据，但这些结果主要停留在一次页面加载中。用户点击分析详情时可以看到结论，却没有一份可回看、可比较、能指出证据来源和数据缺口的研究记录。上一轮已经完成用户隔离和 AI 配置，本 change 将其推进到第一个可审计的研究运行闭环。

## 目标

- 为观察池中的单只股票生成一份服务端确定性的结构化研究报告。
- 把每个结论拆成带来源、观察时间、公式版本、阈值和状态的 `evidence[]`，保留原始指标与数据缺口。
- 按当前登录用户持久化研究运行快照，并支持读取同一股票的历史运行。
- 在现有分析抽屉中提供“生成研究报告”和历史报告入口，帮助中长线价值研究按证据推进。

## 非目标

- 本轮不调用 LLM，不生成买入、卖出、目标价或收益承诺。
- 本轮不把 AkShare、CrewAI 或 Python 运行时引入 Cloudflare Worker；后续通过独立 bridge 接入。
- 本轮不改变既有因子公式、估值 provider 或同步 lease 语义。

## 影响

- `packages/db` 新增用户级 `quant_research_run` 表和迁移。
- `apps/api` 新增研究报告纯函数、repository 和 `/api/quant/research/runs` API。
- `apps/quant-app` 增加报告类型、客户端方法和分析抽屉研究报告区。
- OpenSpec、Vitest、type-check、build 和 Gateway 回归范围扩大到研究运行链路。

## 风险

- 上游估值、财务或分红源失败时，报告必须明确标记缺失，不把缺失当成零值或通过。
- 报告 JSON 是持久化快照，公式升级后旧报告仍需保留 `reportVersion` 和各证据 `formulaVersion`。
- 报告生成会触发多个 provider 请求，先限定为用户主动操作并复用现有超时和错误分类。

## 验收要求

已登录用户对观察池股票生成报告后，API MUST 返回并持久化同一 `runId`、`tsCode`、报告版本和结构化证据；另一个用户的历史查询 MUST 看不到该运行。每条证据 MUST 带有状态、来源、观察时间、阈值和可解释详情；数据缺口 MUST 进入 `missing` 或 `partial` 状态。
