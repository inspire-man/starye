## 方案概览

本轮保持现有 Quant 单页工作流和右侧 `DetailDrawer`，把“研究”作为观察池之上的用户工作层。候选快照仍是服务器生成的技术事实，估值/财务仍由现有接口读取，研究标记是独立用户输入。

## 数据与 API

- 新增 `quant_research_marker` 表：`ts_code` 唯一，保存 `status`、`note`、`review_date`、`created_at`、`updated_at`。
- 新增 migration `0039_quant_research_marker.sql`，使用明确的建表和唯一索引；观察池删除时通过应用层先删除标记，避免遗留孤儿记录。
- 新增 `GET /api/quant/research`，返回观察池全量标记；没有记录的股票由 repository 归一化为 `unreviewed`。
- 新增 `PUT /api/quant/research/:tsCode`，只允许观察池代码和四个状态，成功后读回完整记录。
- `QuantError` 增加 `QUANT_INVALID_RESEARCH_STATUS`，非法状态使用 400；目标不在观察池使用既有 `QUANT_NOT_FOUND`。

## 前端状态

- `researchMarkers` 使用代码索引，首次加载工作区时与观察池/候选并行读取。
- 候选表启用 `DataTable` 的选择能力，组件层只负责最多选 3 只的状态控制；“全选”也只取排序后的前 3 只。
- 对比抽屉先渲染候选技术指标，再按代码并发请求估值和财务快照；单只请求失败写入该代码的错误状态，不影响其他列。
- 分析抽屉顶部的决策卡直接使用当前候选和已有 `researchSummary`，研究标记编辑区使用同一个抽屉，保存后更新本地索引。

## 交互与可读性

- 决策卡顺序固定为：结论边界、命中依据、需要核对、数据新鲜度。
- 对比表使用“股票为列、指标为行”的布局，最多三列，避免宽屏表格继续横向扩张；移动端允许对比表在抽屉内滚动。
- 状态颜色只表达研究工作流状态，不表达收益预测；备注采用多行输入并限制长度，复查日期使用原生日期控件。
- 任何上游缺失显示 `--` 或“暂不可用”，不计算跨股票排名。

## 验证

- API/DB：migration、repository、路由集成测试覆盖幂等、非法状态、非观察池目标和读回。
- Quant：API client 解析、最多三选、决策卡和研究标记保存状态覆盖测试。
- Gateway：桌面端验证决策卡、对比抽屉和保存后状态；390px 验证抽屉滚动和无页面横向溢出。
