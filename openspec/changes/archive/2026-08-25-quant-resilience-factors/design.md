## Context

当前价值质量计算是纯函数，输入来自观察池、Eastmoney 估值、Eastmoney 多期财务报告和本地日线库，结果经 `/api/quant/value-selection` 返回给 Quant 前端。现有 provider 已规范化 `interestCoverage`、`interestBearingDebtRatio`、`cashRatio` 和 `operatingCashflowToRevenue`，无需增加外部接口或 D1 持久化。

## Goals / Non-Goals

**Goals:**

- 以版本化公式补齐长期持有所需的资产负债表韧性和现金流连续性。
- 保留原始值、池内样本数、状态和风险原因，让小观察池和缺失数据可被识别。
- 保持股东回报作为独立证据链，不让可选的 Tushare 分红数据改变核心评分的可用性。

**Non-Goals:**

- 不新增数据库表、缓存层、行业分类或一致预期数据。
- 不把 v2 评分转换成自动买入、卖出或收益预测。
- 不为缺失的资本开支、自由现金流绝对额或行业景气数据编造替代值。

## Decisions

1. **使用五个维度而不是继续堆叠质量指标。** 估值 30、质量 30、增长 20、韧性 15、趋势 5，总分仍为 100；趋势只用于研究时点，避免短期价格信号主导中长线评分。
2. **韧性采用三项同池百分位。** 利息覆盖、现金比率和带息负债率是 provider 已有且含义清晰的字段；不使用 `fcffForward` 作为核心韧性分，因为它的绝对规模会把公司体量混入排名。
3. **现金流连续性使用跨报告非负比例。** 该指标对报告数量不敏感、容易向初学者解释；少于两期时保留缺失，不用单期推断“稳定”。
4. **风险扣分使用绝对门槛。** 相对排名说明“池内位置”，绝对门槛说明“是否可能有结构性风险”，两者同时保留；风险扣分封顶 10 分。
5. **前端复用现有维度网格。** 只扩展合法维度解析和公式文案，动态渲染韧性卡片，避免新增独立卡片层级和重复数据请求。

## Risks / Trade-offs

- [风险] 新公式版本会让同一股票的分数与 v1 不可直接横向比较 → 响应和界面明确显示 `value-quality-v2`，历史 v1 只保留在 Git/归档记录中。
- [风险] Eastmoney 某些股票缺少韧性字段，ready 数量下降 → 返回 `partial`/`insufficient_data` 和具体缺口，不降级为零分。
- [风险] 观察池样本很小时百分位不稳定 → 每个指标继续返回 `sampleCount`，文案明确“仅当前观察池”。
- [风险] 绝对门槛跨行业并不完全等价 → 仅作为风险复核提示，不作为单独买卖结论。

## Migration Plan

1. 先部署纯函数和 client 兼容改动，v2 响应在同一 `/value-selection` 路由生效。
2. 工作台读取新版本并显示五维权重；无数据库迁移和回填步骤。
3. 若上游字段覆盖不足，保留 v2 的缺失状态并通过版本回退到上一提交；不需要数据迁移。
