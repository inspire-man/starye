## Context

当前研究报告已经读取 Eastmoney 的完整财务快照和估值快照，但 `research-report.ts` 只把其中少量字段变成 evidence。AI 因子影响由报告与复核重新计算，研究摘要 JSON 和部分历史快照没有完整保存派生结果。实现需要保持现有五因子、用户配置和新鲜度闸门语义。

## Goals / Non-Goals

**Goals:**

- 用稳定 evidence key 把高价值 provider 字段接入估值和盈利质量因子。
- 以服务端重新计算的结果生成 AI 影响分，并保存评估时间与历史权重边界。
- 让新响应既能显示当前时效门控，也能回看当时的 AI 影响快照。

**Non-Goals:**

- 不改 provider 请求、AI 模型、AI API 传输或确定性因子公式的基本判定语义。
- 不新增 D1 表、迁移、后台队列或自动交易动作。
- 不让 AI 返回的数字直接覆盖 provider 原始数据或确定性推荐。

## Decisions

1. **证据扩展放在研究报告构建层。** 直接从已经传入的 `QuantValuationSnapshot` 与 `QuantFinancialQualitySnapshot` 构建 evidence，避免重复请求 provider；缺失字段沿用 `missing` 状态和既有报告覆盖规则。PS/PEG 作为估值增强证据保留在覆盖分母中但不替代 PE/PB 核心门槛，新增盈利质量字段作为核心质量证据。

2. **AI 影响分使用接受复核的权重归一化。** `support`、`caution`、`oppose` 映射为 100、50、0，仅接受复核参与 `aiScore`；`aiScoreDelta` 是 AI 分减确定性模型分。逐因子 `aiContribution` 使用接受权重归一化后的 AI 分贡献，避免把未纳入因子误算成 0 分。

3. **分离当前派生值与历史快照。** 研究摘要响应继续返回按当前读取时点计算的 `factorImpact`，用于当前新鲜度闸门；摘要 JSON 另保存服务端生成时的 `factorImpactSnapshot`，响应同时返回该快照。决策记录和决策助手把评估时的 `factorImpact` 写入自身快照，旧快照缺字段时按已有复核回退派生。

4. **快照由服务端重建并校验。** 持久化 JSON 中的评估时间和结构经过边界校验；影响数值仍依据报告、历史因子配置、AI 复核和评估时间重算，避免把客户端或模型自报的权重当成事实。

5. **不拆共享数据库结构。** 现有 D1 行已经有版本化 JSON 字段和用户隔离查询，新增字段保持在该边界内，降低迁移风险；API/客户端解析器对旧字段采用显式可选兼容。

6. **在 AI 领域边界归一化字段命名。** 摘要和决策助手解析器读取 camelCase 与 snake_case 的等价字段，再交给同一套版本、枚举、证据引用和内容校验；不在 transport 层做无上下文的全局字符串替换，避免影响普通文本。

## Risks / Trade-offs

- [新增证据可能降低报告覆盖] -> 缺失项显示为真实缺口，因子状态和 AI 闸门保持 fail-closed，并在 UI 提供补数据路径。
- [当前影响与历史快照时效不同] -> 响应同时携带当前 `factorImpact` 与保存时快照，并在界面标注两者的时间语义。
- [旧快照结构不统一] -> 所有新字段可选读取；重算只使用已存在的合法复核和报告 evidence，不补造旧数据。

## Migration Plan

1. 发布兼容代码，先读旧 JSON，再对新生成的摘要/决策快照写入新字段。
2. 通过 API 集成测试验证用户隔离、旧 JSON 和持久化读回；不需要历史数据回填。
3. 如需回滚，旧客户端忽略新增字段，旧 JSON 仍可由当前解析器读取。
