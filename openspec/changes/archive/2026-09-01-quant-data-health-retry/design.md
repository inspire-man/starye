## 设计

### 动作模型

数据健康纯函数为每条非完整、非读取中的数据域返回一个明确动作：日线返回 `open-watchlist`，价值质量返回 `refresh-value-quality`，股东回报返回 `refresh-shareholder-returns`。完整和读取中状态不返回动作。动作标签直接说明执行结果，避免把“进入页面”和“重新读取”混为一谈。

### 页面分发

总览继续复用现有数据健康摘要。App 层根据动作类型调用已存在的 loader；日线只切换到观察池，研究数据直接触发对应读取。loader 自己负责请求并捕获错误，因此动作按钮不会产生未处理的 Promise 错误。

### 最近有效结果

价值质量、股东回报和同步状态的 loader 在开始新请求时只更新 loading 和错误状态，不清空已有结果。只有最新请求成功时才替换结果；最新请求失败时保留旧结果并设置错误状态。研究详情在旧结果存在时继续显示旧结果，并在内容前显示“刷新失败/刷新中”的状态提示；同步面板在旧同步结果存在时也显示读取错误提示。

### 边界

观察池发生变化时仍由现有 `loadWatchlist` 清空与旧样本绑定的研究结果。该清空属于样本切换，不属于刷新失败保留策略。所有动作仍是前端行为，不改变 API 响应和 D1 数据。
