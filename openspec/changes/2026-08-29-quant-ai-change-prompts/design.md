## Context

单股报告页面已经由 `App.vue` 同时渲染研究问答、AI 摘要和 AI 变化解释。上一项已让 `QuantAiResearchQuestion` 公开输入更新与 `nextTick` 聚焦方法，本 change 复用同一 template ref 桥接。

## Goals / Non-Goals

**Goals:**

- 将变化解释核对项转换为当前报告范围内的有界问题。
- 在桌面和窄屏下提供可访问的同级快捷操作。
- 保持快捷动作不提交、不请求 AI。

**Non-Goals:**

- 不改变变化解释生成接口、报告快照、AI prompt 或持久化。
- 不加入变化解释之外的事实、因果判断、买卖建议或收益判断。

## Decisions

- **独立纯函数模板。** 新增变化解释专用提示函数，trim 后在固定前缀和固定后缀之间截断，保证 500 字符限制和后缀稳定可测。
- **统一报告问答 readiness。** 将已有 readiness 变量命名为 `researchQuestionPromptReady`，摘要和变化解释按钮都检查报告存在、问答组件 ref 已建立、报告未生成中且问答未加载。
- **父组件集中转发。** 变化解释组件只发出核对项，`App.vue` 负责调用提示函数和现有问答 ref；问答组件继续作为唯一的输入/聚焦实现。
- **响应式同级布局。** 桌面端使用文本与按钮两列，680px 以下切换单列，按钮进入下一行；核对文本允许任意位置换行。

## Risks / Trade-offs

- [风险] 变化解释生成过程中问答组件短暂不可用 → readiness 为 false 时禁用按钮，事件处理再次检查 ref 和状态。
- [风险] 长核对项挤压按钮 → 只截断问题文本并保留固定后缀，UI 文本使用 `overflow-wrap: anywhere`。
- [风险] 填入新问题后旧回答仍显示 → 与既有问答桥接保持一致，用户主动提交后才刷新回答。

## Migration Plan

无需数据迁移。发布后直接使用现有报告页面；回滚只移除变化解释按钮和模板桥接代码。
