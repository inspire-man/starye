# Starye Hono Route Workflow

Use this skill for an API endpoint or API-to-Vue contract that crosses apps/api, packages/api-types, and an app client.

## Backend pattern

1. Put request schemas in apps/api/src/schemas/ or beside the established route domain, using import * as v from valibot. Define param, query, JSON, and response/domain shapes at the route boundary.
2. Create or extend Hono<AppEnv>() in apps/api/src/routes/. Attach validator for param, query, or json, read validated input with c.req.valid(...), and preserve the existing c.json envelope and status semantics.
3. Use the existing auth boundary: global middleware is assembled in apps/api/src/index.ts; route-specific access uses requireAuth, internal crawler routes use signed/service auth, and database access comes from c.get('db').
4. Mount the router through the chained routes value in apps/api/src/index.ts. export type AppType = typeof routes is the source for Hono RPC inference. OpenAPI is generated by openAPIRouteHandler with hono-openapi and Valibot schemas.

## Consumer pattern

- Dashboard's typed client is apps/dashboard/src/lib/hono-rpc-client.ts: hc<AppType>, the configured Gateway base URL, and credentialFetch with credentials: include.
- @starye/api-types exposes the built API declaration. After a route change, run pnpm --filter @starye/api-types run build before consumer type-checks.
- apps/dashboard/src/lib/api.ts, apps/comic-app/src/lib/api-client.ts, apps/movie-app/src/lib/api-client.ts, apps/blog/app/composables/useApiClient.ts, and apps/quant-app/src/lib/api-client.ts have distinct wrapper boundaries. Preserve a local wrapper when it handles multipart, auth, progress, streaming, provider errors, or deliberate response normalization.
- Quant API responses include strict versioned research/evidence/decision payloads and AI streaming. Parse and validate those payloads in the Quant client; keep API key plaintext out of response models.
- Browser and client requests use the /api path through the Gateway. http://localhost:8080 is the acceptance entry; 8787 and app dev ports are diagnostic.

## Contract checks

- Keep route registration, path parameters, validator input types, status codes, error envelope, auth middleware, and response fields aligned.
- Add a route test with a small Hono<AppEnv> host and app.route(...), plus schema tests for boundary cases. Use API type-check to catch AppType drift.
- For crawler, repair, availability, persistence, or Quant routes, verify returned identity against D1 authoritative readback and the relevant receipt, projection, revision, user scope, or research run.
- Cross API/db/frontend endpoint or data-model work starts with the repository OpenSpec flow. Before changing a shared route handler, run GitNexus route/symbol impact analysis and report affected consumers.
