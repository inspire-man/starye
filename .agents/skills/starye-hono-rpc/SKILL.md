# Starye Hono Route Workflow

Use this skill for an API endpoint or an API-to-Vue contract that crosses apps/api, packages/api-types, and an app client.

## Backend pattern

1. Put request schemas in apps/api/src/schemas/ using import * as v from 'valibot'. Define param, query, JSON, and response/domain shapes beside the route domain where that is the established local pattern.
2. Create or extend new Hono<AppEnv>() in apps/api/src/routes/. Attach validator('param' | 'query' | 'json', Schema) from hono-openapi, read validated input with c.req.valid(...), and return the existing c.json(...) envelope and status semantics.
3. Use the existing auth boundary: global middleware is assembled in apps/api/src/index.ts; route-specific access uses requireAuth, internal crawler routes use their signed/service-auth contract, and database access comes from c.get('db').
4. Mount the router through the chained routes value in apps/api/src/index.ts. export type AppType = typeof routes is the source for Hono RPC inference. The OpenAPI document is generated by openAPIRouteHandler; this project uses hono-openapi with Valibot schemas.

## Consumer pattern

- Dashboard's typed client is apps/dashboard/src/lib/hono-rpc-client.ts: hc<AppType>, the configured Gateway base URL, and credentialFetch with credentials: include.
- @starye/api-types exposes the API type through the built API declaration. After an API route change, run pnpm --filter @starye/api-types run build before consumer type-checks.
- apps/dashboard/src/lib/api.ts, apps/comic-app/src/lib/api-client.ts, apps/movie-app/src/lib/api-client.ts, apps/blog/app/composables/useApiClient.ts, and apps/quant-app/src/lib/api-client.ts have different wrapper boundaries. Preserve a local wrapper when it handles multipart, auth, progress, provider-specific errors, or deliberate response normalization; typed RPC is the default for routes that already expose a usable AppType shape.
- Browser and client requests use the /api path through the Gateway. http://localhost:8080 is the acceptance entry; 8787 and app dev ports are diagnostic.

## Contract checks

- Keep route registration, path parameters, validator input types, status codes, error envelope, auth middleware, and response fields aligned.
- Add a route test with a small Hono<AppEnv> host and app.route(...), plus schema tests for boundary cases. Use API type-check to catch AppType drift.
- For crawler, repair, availability, or persistence routes, verify the returned identity against D1 authoritative readback and the relevant receipt/projection/revision. HTTP 200 alone is an incomplete acceptance signal.
- Cross api/db/frontend endpoint or data-model work starts with the repository OpenSpec flow. Before changing a shared route handler, run GitNexus route/symbol impact analysis and report the affected consumers.

## Verification commands

    pnpm --filter api run type-check
    pnpm --filter @starye/api-types run build
    pnpm --filter dashboard run type-check
    pnpm --filter comic-app run type-check
    pnpm --filter movie-app run type-check

Choose the app checks that consume the route, then verify the canonical Gateway path in a browser or request harness.
