<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| runner receipt -> `validateReceiptCandidate` | untrusted IDs/counts and candidate outcome enter API validation |
| sync payload -> D1 movie/player/source state | controlled crawler payload crosses the write/reconciliation boundary |
| terminal D1 projection -> task detail | stored facts cross into an admin read model |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-20-04 | Tampering | `validateReceiptCandidate` | high | mitigate | query canonical movie/player rows by server-owned movie.id and derive disposition after write/readback |
| T-20-05 | Repudiation | `applyTransition` receipt persistence | medium | mitigate | persist receipt version, content id, source revision and existing transition/attempt facts atomically with bounded summaries |
| T-20-06 | Information Disclosure | sync error/read models | high | mitigate | map failures to enumerated reason codes and redact raw exception, URL, command, workflow, secret and signed material |
| T-20-07 | Denial of Service | player reconciliation | medium | mitigate | use existing D1 batch/parameter-bound writes, bounded candidate IDs/counts, and explicit empty-array semantics without unbounded retry |
</threat_model>
