# Phase 20 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

本阶段只校正现有 Starye Vue 界面的状态边界。Crawler task detail 与 MovieDetail 必须显示同一 `primaryContentId` 的 metadata、source readiness 与 playback proof 三个事实层；Player 只增加 no-source 防护，不新建内容管理入口、播放器架构或营销页面。所有本地验证入口使用 `http://localhost:8080/...` Gateway。

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — 现有 Vue + Tailwind 组件体系；项目不是 React/Next/Vite，shadcn 初始化门槛不适用 |
| Preset | not applicable |
| Component library | `@starye/ui` 现有 `DataTable`、`SkeletonTable`、`ErrorDisplay`、`Toast`、`ConfirmDialog`；不新增第二套组件库 |
| Icon library | `lucide-vue-next`（已有图标库）；状态图标必须配文字，不使用 emoji 作为唯一语义 |
| Font | 继承应用现有 system sans-serif；不引入新字体 |
| Existing visual language | 深色中性背景、深灰次级表面、绿色/teal 主强调、紧凑圆角与表格/详情混合布局 |

### Surface inventory

| Surface | Layout contract | Primary user job |
|---------|-----------------|------------------|
| Crawler task detail | `container` 内的单列任务头 + 两列摘要（窄屏折为单列）+ 可折叠 receipt/source observation | 快速判断 metadata 是否入库、source 是否可用、是否需要受控修复 |
| MovieDetail | 现有影片头部/元数据保持不变；在播放源区前增加 readiness summary；播放源列表只展示可行动字段 | 在同一影片身份下决定播放、刷新或进入修复意图 |
| Player guard | 现有全屏播放器错误/加载层复用；无 eligible source 时展示 no-source guard，禁止创建 xgplayer | 防止 `players=0` 看起来像播放成功 |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` / 既有 dark neutral background | 页面背景、播放器外层、空白区域 |
| Secondary (30%) | `hsl(var(--card))`、`hsl(var(--muted))` | 任务摘要、source summary、详情面板、表头与 skeleton |
| Accent (10%) | `hsl(var(--primary))` / 现有 teal-green accent | 仅用于主动作“查看影片/重试读取”、ready/playback_verified 状态、当前选中 source、focus ring |
| Destructive | `hsl(var(--destructive))` | source_failed、读取失败、不可逆删除或明确破坏性确认；不用于普通 no_source |

Accent reserved for: `播放/查看影片` 主按钮（仅 ready/playback_verified）、`重试读取`、当前选中状态、ready 与 playback_verified 标签、键盘 focus ring。`no_source` 使用 amber/warning token，`repairing` 使用 blue/info token，`source_failed` 使用 destructive token；这些语义色不得替代文字状态。

颜色必须同时满足文字、图标和 `aria-label` 语义；不得仅靠颜色区分五种状态。

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `查看影片`（仅 metadata 已持久化且 source readiness 为 ready/playback_verified 时）；修复入口使用 `查看修复意图`，本阶段不暴露任意命令/来源地址 |
| Empty state heading | `暂无可用播放源` |
| Empty state body | `影片元数据已入库，但当前没有可用来源。可查看受控修复意图；这不是播放成功。` |
| Error state | `来源状态读取失败。请重试读取；在读取成功前不要将影片标记为可播放。` |
| Loading state | `正在读取影片与来源状态...` |
| Source failed reason | `来源写入失败，已保留为可修复状态。请重试读取或查看修复意图。` |
| Repairing state | `受控修复进行中，来源状态尚未确认。` |
| Playback proof note | `已验证浏览器播放`；仅在收到独立 playback evidence 时展示，`ready` 不得自动升级为此状态 |
| SUN-064 copy | `SUN-064：元数据已入库；players=0，当前无来源，可修复。` |
| Destructive confirmation | 本阶段未设置删除/覆盖动作；若既有页面保留破坏性操作，确认文案必须明确 `确认删除/覆盖此记录？`，二次确认后才提交 |

### Status labels and bounded reasons

| Machine state | Visible label | Meaning | Allowed action |
|---------------|---------------|---------|----------------|
| `ready` | `来源就绪` | 至少存在一个 server-owned eligible candidate；不代表浏览器已播放 | `查看影片`、查看来源摘要 |
| `no_source` | `暂无来源` | 读回后没有 eligible source，包含 `players=0` | `查看修复意图`、`重试读取` |
| `source_failed` | `来源失败` | source 写入/读回失败，原因使用有限 code | `重试读取`、`查看修复意图` |
| `repairing` | `修复中` | 已进入受控修复意图，当前 readiness 尚未确认 | `刷新状态`；禁用播放主 CTA |
| `playback_verified` | `播放已验证` | 独立 browser evidence 包含 `playing` 与 `currentTime` 推进 | `查看影片`；可显示验证时间 |

Reason text uses server-owned bounded reason codes mapped to Chinese copy，单条最多 120 个字符、界面最多 2 行；不得展示 raw exception、URL、命令、workflow、secret、签名材料或原始 runner JSON。

## Component and Interaction Contract

### Shared readiness summary

任务详情与 MovieDetail 必须消费同形状的 readiness projection，至少包含：

- `content identity`: 标题、code、`primaryContentId`；详情页显示 code/id tuple，加载与错误态不得伪造 tuple。
- `metadata`: `persisted` 状态与最近持久化时间；仅表示电影行存在。
- `source`: disposition、eligible count、source revision、最近读回时间、bounded reason。
- `playback`: `unverified` 或 `verified`；verified 旁显示 evidence time/summary，不得由 `ready` 推导。
- `receipt`: receipt status 与同一 content identity 的关联；显示摘要，不显示 raw receipt payload。

布局顺序固定为：身份头 → Metadata persisted → Source readiness → Playback proof → Receipt/source summary → bounded actions。三层状态使用独立 label/区域，禁止用一个“抓取成功”徽章覆盖全部事实。

### Crawler task detail

- 顶部显示任务/运行/尝试的脱敏标识和影片身份，不显示来源 URL、命令、workflow、token、secret 或 signed material。
- 用 `DataTable`/紧凑 key-value rows 承载重复扫描字段；状态标签固定在每行同一列，reason 列截断至 2 行，点击/键盘聚焦可展开完整 bounded reason。
- metadata 与 source 用并排 summary blocks；`metadata.persisted` 可为成功而 `source.no_source` 同时出现，视觉上必须是两个独立状态。
- receipt/source 区显示 `content identity matched`、source revision、candidate count 与 disposition；不显示“播放成功”。
- `no_source` / `source_failed` 提供 `查看修复意图` 与 `重试读取`；本阶段动作只触发受控 readback/导航，不让用户填写任意 URL 或命令。
- `repairing` 只显示 `刷新状态`，动作执行中显示 spinner、禁用重复提交，并在结果返回前保留原 disposition。

### MovieDetail

- 保持现有影片标题、封面、元数据、系列导航与播放源区；在 source list 之前插入 readiness summary，不创建第二个 Movie editor。
- ready/playback_verified：主 CTA 为 `查看影片`；source list 仅列 source type/name/quality/eligibility 等受控字段，排序/评分不得单独标记健康。
- no_source：显示空状态 copy、eligible count `0`、repairable 标记与 `查看修复意图`/`重试读取`；隐藏或禁用 `播放`，不显示空播放器占位作为成功反馈。
- source_failed：使用错误 banner + bounded reason；保留影片身份和 metadata，主动作是 `重试读取`，不要把失败降级成普通空列表。
- repairing：显示进行中 banner、最近状态时间与 `刷新状态`；播放按钮 disabled，避免用户误以为修复已完成。
- playback_verified：在 ready 旁显示独立 proof badge；展示简短 evidence summary（`playing`、`currentTime` 推进），不保存或展示完整媒体/签名材料。

### Player no-source guard

- MovieDetail/API 返回 `no_source` 或无 eligible source 时，Player 在任何 xgplayer constructor 前渲染 guard：`暂无可用播放源` + `返回影片详情`。
- `players=0`、全 inactive、source readback failure 均不得初始化播放器、上报 view 或展示 `playing`/成功文案。
- 现有加载、缓冲、source-invalid、网络错误卡片继续沿用；本阶段只确保 no-source 是明确的可修复前置状态，不与 runtime playback error 混淆。

### State transition contract

```text
loading -> metadata.persisted + source.reading
source.reading -> ready                  (eligible candidate exists)
source.reading -> no_source              (0 eligible, including SUN-064 players=0)
source.reading -> source_failed          (bounded write/read failure)
no_source/source_failed -> repairing     (受控修复意图已提交)
repairing -> ready/no_source/source_failed (fresh readback result)
ready -> playback_verified               (独立 browser playing + currentTime evidence)
playback_verified -> ready               (proof stale/absent; never silently claim verified)
```

Receipt persisted、metadata persisted、provider/repair success 与 playback proof 不得互相自动升级。任何 readback 未完成时显示 `状态读取中`，不显示 ready。

## Responsive and Accessibility Contract

- Desktop（>= 1024px）：task detail summary 使用 2 列，主内容最大宽度沿用 `container`；status/action 固定在可扫描列，不因 reason 长度改变表格列宽。
- Tablet（768-1023px）：summary 仍可 2 列但 action group 允许换行；source summary 保持最小宽度并可横向滚动，不压缩 label 到不可读。
- Mobile（< 768px）：所有 summary 折为单列；操作按钮全宽或两列固定 44px 高度；状态 label 与 reason 分行；表格改为 stacked rows/横向滚动，禁止页面整体横向溢出。
- 长标题、code、reason 使用 wrap/ellipsis + 完整可访问名称；不得让文字覆盖状态徽章或动作按钮。关键身份字段允许换行，不得用视觉裁剪隐藏唯一身份。
- 状态区域使用 `role="status"`（loading/repairing）或 `role="alert"`（source_failed）；异步状态更新通过 `aria-live="polite"`，错误不抢夺焦点除非由用户提交动作触发。
- 每个状态 label 同时包含文本与语义图标；按钮使用明确动词，icon-only 关闭/刷新按钮必须有 `aria-label` 与 tooltip。
- 键盘顺序：身份链接 → readiness 状态 → receipt 摘要 → 主动作 → 次动作；focus ring 使用 accent token，不得只依赖 hover。
- 对比度满足 WCAG AA；`prefers-reduced-motion` 下禁用 skeleton shimmer/transition，仅保留静态 loading indicator。
- 受 R18 访问控制拒绝时沿用现有权限错误体验，不泄露来源或 receipt 内容。
