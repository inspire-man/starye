## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Human/browser -> Gateway Dashboard | Credentials, selected target context, and repair command begin at an authenticated boundary. |
| Gateway browser -> production repair/provider | Server registry and provider lifecycle cross into GitHub Actions-controlled execution. |
| Browser media -> verifier -> API/D1/artifact root | Browser observations are untrusted; only bounded summary/reference crosses to persistence. |
| D1/artifact root -> human report | Evidence must remain immutable, redacted, tuple-bound, and non-public. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-24-20 | Spoofing | production session/target | high | mitigate | Require signed authenticated Dashboard session and registry-selected target before dispatch. |
| T-24-21 | Tampering | production tuple/matrix | high | mitigate | Generate fresh IDs from the command path and compare every live/D1/artifact/UI identity. |
| T-24-22 | Repudiation | proof report/history | medium | mitigate | Persist immutable pair and bounded outcome/rejection history for pass, fail, and checkpoint. |
| T-24-23 | Information Disclosure | artifact/report | high | mitigate | Apply allowlist redaction and scan JSON plus Markdown before D1 reference submission. |
| T-24-24 | Denial of Service | browser/provider orchestration | medium | mitigate | Bound precondition polling, provider window, media observation window, source retries, and proof rerun allocation. |
