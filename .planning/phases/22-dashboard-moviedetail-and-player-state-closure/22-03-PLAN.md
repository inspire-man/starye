<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repair API -> Dashboard DTO | task/run/readiness/receipt fields cross into an authenticated admin UI. |
| Dashboard DTO -> same-movie link | server-owned movie code becomes a public MovieDetail route parameter. |
| task polling -> browser timers | repeated visible-page reads can amplify load if lifecycle cleanup or deduplication fails. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-09 | Information disclosure | repair task response and Dashboard projection | high | mitigate | Add only movie id/title/code to the existing bounded DTO and retain existing route tests excluding raw runner, URL, token and signature fields. |
| T-22-10 | Tampering | same-movie terminal link | medium | mitigate | Build the link from the server-owned validated movie code and keep it on the existing `/movie/:code` route; do not accept a caller-supplied URL. |
| T-22-11 | Denial of service | visible-page polling | medium | mitigate | Keep one 5-second interval per mounted visible page, stop it on hidden/unmount, and cover fake-timer transitions in Crawlers tests. |
| T-22-12 | Repudiation | attempt/log/receipt history | medium | mitigate | Preserve task detail runs, selected attempt, safe logs and receipt projections while focusing the latest repair task; never replace history with a terminal summary only. |
| T-22-SC | Tampering | package installs | low | accept | This plan adds no package installation; existing workspace dependencies remain the supply-chain boundary. |
</threat_model>
