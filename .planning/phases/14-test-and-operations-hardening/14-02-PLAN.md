<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer -> run directory | Generated build input crosses from pure validated text to filesystem materialization. |
| materialized input -> Pages build | Local/CI handoffs pass generated paths to child builds. |
| successful build -> dist artifact | The final deployable redirect file becomes part of a Pages output directory. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-02-01 | Tampering | materialized redirect input | high | mitigate | Task 1 confines paths to the run directory and parses renderer output before exposure. |
| T-14-02-02 | Tampering | prepared Pages output | high | mitigate | Task 2 validates and tests the contained path in JSON and GitHub output. |
| T-14-02-03 | Tampering | `dist/_redirects` write | high | mitigate | Task 3 uses a closed surface mapping, waits for both builds, and atomically writes only final output. |
| T-14-02-04 | Information disclosure | prepared/build environments | medium | mitigate | Tasks 2 and 3 preserve current allowlisted child environments and test that secrets are absent. |
| T-14-02-05 | Denial of service | stale build artifact | medium | mitigate | Task 3 verifies failure paths write no output and cleanup removes transient input. |
</threat_model>
