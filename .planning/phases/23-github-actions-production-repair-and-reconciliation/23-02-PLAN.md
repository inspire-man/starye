<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| GitHub workflow to production runner | Workflow environment and binding fields reach an untrusted execution process. |
| Runner to internal API | Signed lifecycle and source facts cross from provider execution into the API. |
| Claimed snapshot to adapter registry | Snapshot data controls which operation-specific source code runs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-23-05 | Tampering | Workflow dispatch inputs | high | mitigate | D-03 fixed four-input validation and target-profile checks reject arbitrary operation or target controls. |
| T-23-06 | Elevation of Privilege | Adapter registry | high | mitigate | D-01, D-04, and D-05 validate the claimed snapshot before adapter selection and never fall back to ordinary crawl. |
| T-23-07 | Spoofing | Runner callback envelope | high | mitigate | D-07 and D-10 bind signed callbacks to run, application attempt, provider tuple, sequence, event ID, nonce, and age. |
| T-23-08 | Information Disclosure | Runner callback payload | medium | mitigate | Adapter and callback clients serialize bounded source facts and keep secrets, source bodies, and raw runner output out of events. |
| T-23-09 | Denial of Service | Lease/heartbeat loop | medium | mitigate | Existing lease checkpoints and bounded callback retry prevent unbounded runner or callback work. |
</threat_model>
