# Phase 13 - Validation Strategy

> This is the current validation map for all 23 plans and all 50 tasks. The typed lifecycle remains `pre_ingest` -> `resolved_pending_observation` -> terminal `resolved`. Only the first state may have `itemId: null`; only terminal `resolved/passed` can prove the chain. A checkpoint or pending pair is schema-valid non-success, never a promoted pass. Plans 13-21 and 13-22 are immutable blocked runtime history. Plan 13-23 opens the current generator-only TDD repair and exact authorization/recovery gate before any fresh PID operation.

The canonical command contracts after Plan 13-14 are intentionally distinct:

- Root `smoke:data-chain` and `smoke:data-chain:verify` preserve the called CLI's raw `0|1|2` result at the actual root pnpm process.
- Root `smoke:data-chain:handoff` is binary: `0` means an exact artifact-backed pending handoff is ready; `1` means not ready. An unexpected inner `2` is normalized to handoff `1`.
- Runner/verifier parsing and verification remain fixed to `DATA_CHAIN_EVIDENCE_ROOT`; no env var, CLI flag, config, or alternate root override exists. Handoff adds dedicated import-safe `parseDataChainHandoffArgs`, which tokenizes only mode/target/run, accepts no evidence-root flag, and performs no filesystem/path operation.
- The handoff static prelude imports no Node path/filesystem module and no runner/verifier/surface/evidence owner. A process/import-hook regression proves invalid target/evidence-dir/unknown/duplicate/value-less input exits before any lazy module load or path/factory/storage/downstream call; a valid tracked target resolves first, then lazily loads those owners and enters core. No production evidence-root override is added.
- After dedicated mode/run parsing, `runDataChainHandoffCli` resolves target through `resolveTargetProfile`/`isTargetProfileId` before any path-module call or dependency-factory construction. Unknown/traversal/POSIX-absolute/Windows-drive/UNC/backslash/separator/encoded-separator forms return binary `1` with only non-reflective `invalid_target`; any canonical/noncanonical/equals-form `--evidence-dir` likewise rejects before path/factory/storage/downstream.
- Imported `runDataChainHandoffCore` accepts only a validated resolution, closed mode, and validated runId. Its type/runtime contract has no raw target, evidenceRoot, path bundle, derivation callback, or resolver injection; forged/untracked resolutions fail before path derivation/storage.
- One `deriveDataChainHandoffPaths` uses fixed root plus validated targetId/runId/mode. `path.posix`/`path.win32` lexical guards precede native resolution; host `path.relative` strict-descendant plus exact expected-path equality rejects equality, parent/absolute/drive/UNC/backslash/case/volume escape, alias, same-directory shadow, swapped peer, and wrong-mode marker before filesystem access.
- Core freezes one readonly exact path bundle. Storage operations receive that bundle and return only pair/content/reservation/write status, never replacement paths. The OS-temp adapter may map only after exact-bundle assertion; mutation, malicious extra path returns, or shadow files cannot redirect I/O.
- Before reservation, the imported handoff core requires both exact JSON/Markdown paths absent. Complete/partial pre-existence or a non-ENOENT inspection error on either peer emits exactly one closed immutable-refusal result, returns binary `1`, and invokes reservation/runner/verifier/provider-facing/read/write dependencies zero times without disclosure or peer mutation.
- Only pair-neither may reserve. It atomically exclusive-creates a zero-byte `<mode>.attempt` (`local.attempt` or `remote.attempt`) inside canonical `<target>/<run>` using Node `open(..., 'wx')` or an equivalent no-clobber primitive. Creation is the ownership linearization point before every runner/provider/verifier call. `EEXIST`/concurrent loser emits only `attempt_already_reserved`; any other reservation failure emits only `attempt_reservation_unavailable`; both are binary `1`, downstream-free, and redact raw paths/errors.
- Attempt markers are first-class untracked artifacts and are never deleted, overwritten, repaired, reused, or backfilled, including after checkpoint/failure/crash. Marker-only state blocks re-entry but never satisfies the exact JSON/Markdown verifier. Reservation applies only to the new p13-17 run; historical runs receive no markers.
- After `remote.attempt` ownership, handoff invokes one closed status-only official selected-target live preflight. Unmet writes and pair-verifies `pre_ingest/remote_preflight/target_preflight_unmet` with `itemId:null`, binary handoff `1`, and zero runner/fixture/D1/API/browser/provider mutation; checkpoint write/verify failure retains marker-only non-success. Passed preflight immediately invokes the sole remote runner while preserving its existing internal defensive gates.
- Actual-root pnpm process tests prove only raw/binary exit propagation through a controlled test-process module boundary. They pass no temp/noncanonical evidence root; collision classification and downstream counts come only from the imported production core matrix.
- Artifact-only `smoke:data-chain:verify` remains authoritative for pending/terminal state. It never runs the runner, repairs evidence, or constructs browser receipts.
- The historical Plan 13-12 nested-pnpm assumption is recorded as failed and superseded. It must not be restated or reused as if outer `1` meant pending.
