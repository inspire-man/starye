<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| GitHub Actions runner to internal callback route | Provider execution sends signed but untrusted event bodies into the API. |
| Callback route to D1 repository | Validated event facts can request state, receipt, or source projection changes. |
| Callback result to audit/UI projection | Outcome data crosses into bounded API responses and later Dashboard history. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-23-15 | Spoofing | Signed callback route | critical | mitigate | Verify raw-body HMAC, key validity, age, path binding, run/attempt/provider tuple, event ID, and nonce before parsing. |
| T-23-16 | Replay | Event identity store | high | mitigate | D-10 and D-13 classify identical replay, body conflict, and stale sequence into persisted bounded outcomes. |
| T-23-17 | Tampering | Receipt/source projection | critical | mitigate | D-11 CAS and D-12 readback equality prevent old or mismatched receipts from changing current source state. |
| T-23-18 | Information Disclosure | Callback responses and facts | medium | mitigate | D-17 returns only bounded outcome and source/provider facts; signatures, secrets, raw runner JSON, and source bodies remain excluded. |
| T-23-19 | Denial of Service | Callback parser | medium | mitigate | Strict size, identifier, timestamp, sequence, and array bounds reject unbounded event payloads before repository work. |
</threat_model>
