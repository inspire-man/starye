## Goal

Prevent transient Cloudflare/Wrangler read-check failures from aborting Pages deployments while preserving fail-closed behavior for genuinely missing resources and keeping secrets out of diagnostics.

## Tasks

1. Update `packages/config/src/deployment-target/live-checks.ts` so failed read-only checks retry a bounded number of times and report the selected resource, attempt count, exit status, and a redacted diagnostic summary.
2. Extend `packages/config/src/deployment-target/__tests__/live-checks.test.ts` with transient-retry and redaction regression coverage.
3. Run focused config tests, type/lint validation as available, GitNexus change detection, commit the scoped fix, push `main`, and inspect the resulting `Deploy Auth Service` run.

## Verification

- Existing successful live-check and missing-resource behavior remains unchanged.
- A transient executor failure succeeds after retry.
- Exhausted failures identify the resource and never expose token-like values.
- `git diff --check` and GitNexus `detect_changes` pass before commit.
